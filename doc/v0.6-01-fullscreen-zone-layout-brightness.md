## 背景与目标

v0.5 交付了可交互 3D 展示站。实际跑起来后暴露三件事，本版一并处理：

1. **舞台没法全屏**。`.stage` 固定 16:10 且被右侧 348px 分区面板挤压，100㎡ 六分区信息量又大，读者只能缩放浏览器窗口去看细节。
2. **两个分区看不出陈设**。实测截图：`_probe-back-before.png` 里后勤区机位被 2.3m 高的卫生间体块与墙帽挡死，只剩一片米色墙加一个灰色方块；`_probe-quiet-before.png` 里静音区被两个 2.22m 电话亭横在机位与座位之间，10 个软座被 3 块屏风夹成 4–6cm 的缝，软座与电话亭还互相穿模。两张图都印证了同一件事：**东西堆在分区南缘，正好挡在相机与内容之间**。
3. **整体偏暗发闷**。大面材质集中在深棕（`wallCap #6b4a32` 压顶、`base #5c3d28` 踢脚、`woodDark #5e3f29`、`charcoal #3b2a21`），场景没有 environment map，夜谈期再叠 `ambient 0.18` 与底色 `#3B4356`。

目标：舞台可全屏；两个分区一眼读得出「干什么的、怎么走的」；四个时段都更通透，但昼夜仍分得清。

## 已确认决策

| 项 | 决定 |
|---|---|
| 静音区改造力度 | **重排 + 每座加小桌板**（保留 10 座 / 2 亭 / 屏风 / 书架的规范配置，只改排布与补工作面） |
| 提亮范围 | **四时段整体提亮，夜景保住夜感**（夜间只抬暗部可见度，不抬整体亮度） |
| 全屏范围 | **只全屏 3D 舞台本体**（Canvas + 四角浮层 + 3D 分区标签），时段按钮与讲座角形态切换条留在页面上 |
| 依赖 | 不新增。`naive-icons` 125 个导出里没有 fullscreen/expand 类图标，全屏图标用内联 SVG |

## 坐标事实（实施前已核对源码）

- 房间 12(X) × 8.33(Z) × 3.2(H)，全场景包在 `ROOM.offset = [-6, 0, -4.165]` 内（`src/data/room.ts:13`）。X 0→12 西→东，Z 0→8.33 北→南。
- **北墙 X 7.93–12.21 段是满高实墙**，X 0–8 才是玻璃幕墙（`RoomShell.tsx:47-67,174-175`）。静音区北缘（X 8–12）挂得住实墙。
- **东墙与南墙剖切到 0.8m**（`RoomShell.tsx:177-179`），娃娃屋视角从东南俯视。因此**任何放在分区南缘或东缘的高构件都会挡机位**——这是本次两区重排的第一原则。
- 讲座角可移动隔断在 lecture / circle 形态落在 x≈8.06、Z 3.16–8.48（`layouts.ts:90,98`），与后勤区东缘（x≤8）相邻。
- `ZONE_ANCHORS[zone]` 同时喂 `Zones.tsx` 的家具位与 `Occupants.tsx` 的人流位（`Occupants.tsx:47` 用 `slice(0, count)`）。**家具一动，锚点必须同步**，且顺序要保证「前排优先」（`occupancy` 大的时段人流先落在前排）。
- `room.ts` 的分区矩形与 `config` 必备物件字段属 v0.5 定下的规范（文档标注「不得改动」），本次**只改坐标、不改清单**。

## 一、3D 舞台全屏

**范围**：只全屏 `.stage` 本体。时段按钮（`.mode-bar`）与讲座角形态切换条（`.layout-bar`）留在页面上。

### 改动

- `src/ui/SceneSection.tsx`
  - `useRef` 指向 `.stage`；`useState<boolean>` 记录全屏态。
  - `useEffect` 监听 `fullscreenchange`，Safari 补 `webkitfullscreenchange`，用于同步状态——按 Esc 退出时按钮图标与文案自动回落。
  - `toggle()`：进入用 `el.requestFullscreen?.()`，回退 `el.webkitRequestFullscreen?.()`；退出用 `document.exitFullscreen?.()` / `document.webkitExitFullscreen?.()`。两个 API 都不存在时按钮 `disabled`（iOS Safari 对非 video 元素不支持全屏）。
  - 在 `.stage-tr` 浮层内、`复位` 按钮**之前**插入全屏按钮，沿用 `<Button size="small" type="default">`。
  - 图标：内联 SVG（16px，四角括号，展开/收起两态）。`naive-icons` 无对应图标，不为此新增依赖。
- `src/styles/global.css` `.stage` 段（现 252–269 行）后追加：

  ```css
  .stage:fullscreen,
  .stage:-webkit-full-screen {
    aspect-ratio: auto;
    min-height: 0;
    width: 100vw;
    height: 100vh;
    height: 100dvh;
    border-radius: 0;
    border: none;
    box-shadow: none;
  }
  ```

  `dvh` 不被支持的浏览器回落到前一条 `100vh`。

### 为什么全屏元素选 `.stage` 而不是 canvas

- drei 的 `<Html>`（分区标签）portal 到 Canvas 的父容器，若全屏元素是 canvas，标签会掉出可视区。
- R3F 的 Canvas 用 ResizeObserver 量父容器，`.stage` 变尺寸后画布自动跟随，无需手写 resize 逻辑。

## 三、3D 整体提亮（保留夜感）

**原则**：先加光（保留材质对比），再小幅提亮最暗的几档材质色；夜景只抬「暗部可见度」，不抬整体亮度。

### 3.1 光照

| 位置 | 现值 | 新值 | 说明 |
|---|---|---|---|
| `WorkshopScene.tsx:26` `toneMappingExposure` | 1.08 | 1.16 | 全局最直接的一档，+7% 属安全区间 |
| `Lighting.tsx:15` 环境光系数 | `* 1.35` | `* 1.5` | 抬暗部，阴影面不再发闷 |
| `Lighting.tsx:16` 半球光系数 | `* 1.3` | `* 1.45` | 补向下面 |
| `Lighting.tsx:37-43` 室内补光 | `2.4 / 0.9`，`distance 16` | `3.0 / 1.5`，`distance 19` | **夜间抬幅大于白天**，专救「南侧家具发黑」 |
| `RoomShell.tsx:224-230` 吊灯 `distance` | 7.5 | 9.0 | 9 盏吊灯覆盖到 3.13m 深的静音区末端 |

### 3.2 时段参数（`src/data/timeModes.ts`）

| 时段 | 字段 | 现值 | 新值 |
|---|---|---|---|
| morning | ambient / hemi / sun | 0.45 / 0.5 / 1.0 | 0.5 / 0.56 / 1.05 |
| morning | skyColor | `#F1E7D8` | `#F5EDE0` |
| cocreate | ambient / hemi / sun | 0.55 / 0.7 / 1.4 | 0.6 / 0.76 / 1.45 |
| cocreate | skyColor | `#F7EFE1` | `#FBF5EA` |
| class | ambient / hemi / sun | 0.4 / 0.45 / 0.8 | 0.46 / 0.52 / 0.88 |
| class | skyColor | `#F2DFC9` | `#F6E6D3` |
| **night** | ambient | 0.18 | **0.24**（只抬暗部可见度） |
| **night** | hemi sky / ground | `#4A5A6B` / `#3A2A20` | `#55647A` / `#46362C` |
| **night** | sun | 0（关） | 0（保持） |

四档 `ambient` 与 `skyColor` 同向小幅抬、`night` 抬幅最小 → 时段之间的相对关系不变，用户仍能一眼分出「白天 vs 夜谈」。

### 3.3 材质色板（`src/scene/palette.ts` 的 `C`）

只动最暗、且大面积出现的五档，每档提 8–14%：

| 键 | 现值 | 新值 | 影响 |
|---|---|---|---|
| `wallCap` | `#6b4a32` | `#7d5c41` | 墙顶压顶 / 窗框 / 门套 / 踢脚帽——最显眼的深色轮廓线 |
| `base` | `#5c3d28` | `#6b4c34` | 踢脚线 |
| `woodDark` | `#5e3f29` | `#6d4c33` | 椅框 / 椅背 / 书架 / 屏风 / 吧台基座 |
| `charcoal` | `#3b2a21` | `#48352a` | 柜体 / 设备外壳 |
| `fabricDeep` | `#8b5c3b` | `#9a6a47` | 软座扶手 |

**不**动 `floor #d3a674`、`wall #f2e5d2`、`paper`、`screen`（深色是刻意的设备观感）、`wood #8f613c`（已属中调）。

`C` 的改动会连带影响 `RoomShell` 的 `Wall` 压顶、`Furniture` 的 `M.*` 与 `Occupants` 的 `PANTS`，需一并目测确认。`global.css` 顶部的 `--walnut` / `--espresso` 是 UI 层变量，**不动**——本次只调 3D 层。

## 风险与回退

| 风险 | 回退 |
|---|---|
| `exposure 1.16` + 环境光 `×1.5` 叠加后，`cocreate` 的浅色面（`wall #f2e5d2`、`paper`、`top #e9d6b8`）过曝发白 | 优先回退 `toneMappingExposure` → 1.12、`wallCap` → `#76563c`，其余不动 |

| `ToiletBlock` 参数化时改错相对坐标导致体块散架 | 改动集中在单个组件内，若出错按原 9 个 mesh 的绝对坐标逐个换算回相对值 |
| 静音区三排软座 + 10 张小桌板使 draw call 上升 | 小桌板已用单个 `merged` 几何 + `<Instanced>`，10 张只占 1 个 draw call |

### 与计划的偏差（如实记录）

| 计划 | 实际 | 原因 |
|---|---|---|
| 静音区「三排软座 + 每座一块小桌板」，按计划表给的 5 座/排 + 独立排布 | 3 排 × 3 座 + 西南角单人位 = 10 座 | 12.5㎡ 内 5 座/排（列距 0.8m）会把分区封死——脚本实测自由格仅 216/31400，无人能走动。3 座/排才留出东侧主通道与西、南环形通道（自由格 2955+） |
| 计划写「屏风插进两排之间的空档」 | 屏风改放西、东两侧空档 | 三列座位的列间空档仅 17cm，放不下 7cm 厚的屏风加净距；东西两侧各有 1m 以上空档 |
| 计划给后勤区留 0.7m 主通道、洁净度要求更高 | 自检标准放宽到 0.6m 净宽 | 7 件家具（合计 7.15㎡）塞进 15.6㎡，0.7m 通道在数学上放不下；0.6m 是后勤服务动线的现实最小值 |
| 小桌板计划做成 `<SideTable>` 组件逐个渲染 | 改为 `SIDE_TABLE_GEO` + `<Instanced>` | 10 个相同桌板走实例化只占 1 个 draw call，且与软座的 `ARMCHAIR_GEO` 用法一致 |
| 计划表里 `SinkCounter` / `StorageRack` 靠改内部实现适配朝向 | 改为加可选 `ry` 传参 | 这两个组件被多个分区共用，改内部实现会外溢；加可选参数默认行为不变，零风险 |
| 全屏图标原计划找 `naive-icons` 里的展开类图标 | 改用内联 SVG | 核实 125 个导出后确认没有 fullscreen/expand/scale 类图标；`ExternalLinkIcon` 语义不符。为此新增一个内联 SVG 组件（16px，四角括号两态），不引新依赖 |
| 计划里写了 3D 标签在 `:fullscreen` 下的表现需实测 | 未能实测 | headless 浏览器的 Fullscreen API 被沙箱拦截（`Permissions check failed` / `API can only be initiated by a user gesture`）。已改为验证「按钮状态机 + 能力检测 + CSS 规则已加载」三项静态事实，真机全屏表现请在桌面浏览器复核 |

### 遗留与建议

- **全屏待真机复核**：脚本与规则都已就位，但无头环境无法进入全屏，建议在桌面 Chrome / Edge 点一次确认 Esc 退出后按钮文案回落、Canvas 自适应无拉伸。
- **静音区密度**：12.5㎡ 塞 10 座 + 2 亭 + 书架 + 屏风后，东侧主通道与西、南环形通道都只剩 0.6m 量级。视觉上成立，但若后续要把该区画进施工图，建议复核「10 座」是否要减到 8 座换更宽的通道。
- **无自动化测试**：仓库仍无测试框架，本次的净距与通行核验靠一次性脚本完成（脚本未纳入版本管理）。若这类布点校验要常态化，可把脚本移进 `scripts/` 并接进 `npm run typecheck`。
- **工作区残留**：`_check-back.mjs` / `_check-quiet.mjs` 两个一次性自检脚本与 `_v06-*.png` 截图只在本地留痕，不入库；`.gitignore` 已按 `_` 前缀约定忽略 `_*.png` / `_*.mjs`（发布前已确认根目录无遗留脚本）。
